# אירוע Heroku — 22.03.2026

## מה קרה

Heroku נפל, שולמה דמות שדרוג, והשרת חזר לפעולה עם **10 dynos** במקום 1.
כתוצאה: לא הגיעו צ'אטים נכנסים — לא בהיסטוריה ולא מה-socket.

---

## מה זה Dyno?

Dyno = מחשב וירטואלי נפרד שמריץ את קוד Node.js.

```
Dyno web.1  → מחשב 1 עם Node.js
Dyno web.2  → מחשב 2 עם Node.js
...
Dyno web.10 → מחשב 10 עם Node.js
```

כל dyno **עצמאי לחלוטין** — לא חולקים זיכרון, לא מדברים אחד עם השני.

---

## למה 10 Dynos שבר הכל

### בעיית State In-Memory

socket.io שומר חיבורים בזיכרון של אותו dyno:

```js
// רק בזיכרון של web.3:
activeUsers = { "0541234567": socket_connection }
```

Heroku מחלק תנועה אקראית:
```
משתמש נכנס  → web.3
נציג נכנס   → web.7
```

כשמשתמש שולח הודעה, web.3 מפרסם לנציגים — אבל הנציג על web.7 **לא שומע כלום**.

### בעיית שגיאות 400

socket.io עובד בשני שלבים:
1. HTTP polling — בדיקה ראשונית
2. Upgrade לWebSocket — חיבור קבוע

בדיקה הראשונית הגיעה ל-web.3, ה-upgrade הגיע ל-web.7.
web.7 לא מכיר את החיבור → **שגיאה 400.**

## מה עשינו

### שלב 1 — Session Affinity
```bash
heroku features:enable http-session-affinity
```
מבטיח שכל לקוח תמיד מגיע לאותו dyno → פתר את שגיאות ה-400.

עדיין לא פתר: משתמש על dyno אחד, נציג על dyno אחר — לא מדברים.

### שלב 2 — צמצום ל-1 Dyno
```bash
heroku ps:scale web=1
```
כולם על אותו מחשב. socket.io עובד כרגיל.

---

## למה 1 Dyno מספיק

Node.js הוא async/event-driven — לא חוסם. dyno אחד מטפל בקלות באלפי חיבורים במקביל.

הצוואר בקבוק האמיתי הוא MongoDB (כל הודעה = `updateOne`) והזיכרון (Standard-1X = 512MB).

**מתי לשדרג:** כשיופיעו בלוגים `Error R14 (Memory quota exceeded)` או response times > 1-2 שניות באופן עקבי.

---

## מה לגבי היסטוריה שאבדה

- הודעות שנשמרו ב-MongoDB לפני הנפילה → **קיימות ושלמות**
- הודעות שנשלחו בזמן שה-socket נכשל לחלוטין → **לא הגיעו לשרת, אבדו**

---

## הפתרון לעתיד (כשיהיה עומס אמיתי)

**Redis Adapter לsocket.io** — מאפשר multi-dyno אמיתי:

```
Redis: { כל המשתמשים והנציגים }
         ↑        ↑        ↑
       web.1    web.2    web.3
```

כל `io.emit()` עובר דרך Redis ומגיע לכל הdynos.
פלאגין: `socket.io-redis-adapter` — שינוי של כמה שורות קוד.
עלות: ~$15-30/חודש עבור Redis on Heroku.

**לא צריך עכשיו** — להוסיף רק כשיש עומס אמיתי.
